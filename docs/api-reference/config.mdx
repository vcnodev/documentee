# Config Reference

This page documents the current Documentee configuration surface. Update it whenever config fields change.

## site

`site.name` is required and appears in generated metadata and navigation. `site.url` enables absolute canonical URLs, sitemap URLs, and robots sitemap links. `site.basePath` prefixes internal links and root-relative assets for project-hosted sites such as GitHub Pages repositories. `site.description` and `site.logo` are optional.

## content

`content.directory` selects the Markdown/MDX source directory. The default is `docs`.

## navigation

`navigation` is an array of groups:

```ts
{
  group: "Start",
  pages: ["docs/index", "/generated-route"],
  openapi: "core"
}
```

`pages` accepts source file references or absolute routes. `openapi` points at an `openapi.specs` id and adds operation routes for that spec.

## versions

`versions` adds versioned content roots:

```ts
{
  id: "v1",
  label: "Version 1",
  routePrefix: "/v1",
  content: { directory: "docs/v1" },
  default: false,
  latest: false,
  deprecated: false
}
```

Version ids must be unique. Route prefixes must be unique. Only one version can be marked as default, and only one version can be marked as latest. The static version switcher shows `Latest` and `Deprecated` badges when `latest` or `deprecated` are enabled. Routes for the latest version emit canonical metadata that points to the matching unversioned route.

## i18n

`i18n` adds locale metadata and locale-prefixed translated docs routes:

```ts
i18n: {
  defaultLocale: "en",
  locales: [
    { code: "en", label: "English" },
    { code: "fr", label: "Français" },
    { code: "ar", label: "العربية", dir: "rtl" }
  ]
}
```

The default locale stays unprefixed unless `prefixDefaultLocale` is `true`. Non-default locale content is loaded from folders under the configured content directory, such as `docs/fr/index.mdx` and `docs/ar/index.mdx`. RTL locales set `<html dir="rtl">` and appear in the generated locale switcher.

`i18n.defaultLocale` must be included in `i18n.locales`.

## openapi.specs

`openapi.specs` defines API references:

```ts
{
  id: "core",
  name: "Core API",
  source: "./api/openapi.yaml",
  routeBase: "/api-reference/core",
  version: "v1",
  playground: {
    enabled: true,
    baseUrl: "https://api.example.test",
    auth: "bearer",
    apiKeyName: "x-api-key",
    apiKeyLocation: "header",
    environments: [
      { name: "Production", baseUrl: "https://api.example.test" },
      { name: "Sandbox", baseUrl: "https://sandbox.example.test" }
    ]
  }
}
```

`id` and `source` are required. `routeBase` defaults to `/api-reference`. `version` connects a spec to a configured version. `playground` controls the browser try-it UI.

## playground

`playground.enabled` defaults to `false`. `playground.auth` can be `none`, `bearer`, or `apiKey`. `playground.apiKeyLocation` can be `header` or `query`. `playground.environments` adds named base URL presets to the try-it UI. Browser requests still depend on the API CORS policy.

## search.provider

`search.provider` can be `none` or `pagefind`. `pagefind` generates `/search/` with grouped static results, search index summary counts, and Pagefind UI assets. Pagefind assets load only on `/search/`; ordinary docs pages use a lightweight grouped suggestion modal.

## assistant

`assistant` is disabled by default. Enable it only when you provide your own endpoint:

```ts
assistant: {
  enabled: true,
  endpoint: "/api/docs-assistant"
}
```

When enabled, Documentee renders a small ask-docs form that sends the query plus current route, page title, and URL to `assistant.endpoint`. The endpoint can be a site path or an `http`/`https` URL. Documentee does not implement an assistant backend.

## feedback

`feedback` is disabled by default. Enable it only when you provide your own collection endpoint:

```ts
feedback: {
  enabled: true,
  endpoint: "https://example.com/docs-feedback"
}
```

When enabled, Documentee renders helpful and not helpful buttons with an optional comment field. The opt-in script sends the current route, page title, vote, and comment to `feedback.endpoint`. The endpoint can be a site path or an `http`/`https` URL. Documentee does not host or store feedback responses.

## analytics

`analytics` is disabled by default. Use `provider: "custom"` to attach an external analytics script without adding a provider dependency to Documentee:

```ts
analytics: {
  provider: "custom",
  scriptSrc: "https://analytics.example.com/script.js"
}
```

Documentee renders a single deferred script tag only when `analytics` is configured. `scriptSrc` must be a site path or an `http`/`https` URL; inline JavaScript and dangerous URL protocols are rejected.

## theme

`theme.designSystem` selects a bundled visual system. It can be `minimal-technical`, `modern-glass`, `api-ide`, `enterprise-knowledge`, `premium-editorial`, `sci-fi-console`, `api-observatory`, or `knowledge-graph`. Each design system includes light tokens and dark-mode tokens when `darkMode` is `true`.

`theme.overrides` customizes the selected design system:

- `primaryColor`
- `accentColor`
- `backgroundColor`
- `textColor`
- `mutedTextColor`
- `borderColor`
- `codeBackgroundColor`
- `fontFamily`
- `codeFontFamily`
- `radius`
- `navWidth`
- `contentWidth`
- `contentPadding`
- `densitySpace`
- `cardRadius`
- `bodyFontSize`
- `h1Size`
- `h2Size`
- `lineHeight`
- `headingWeight`
- `shadowCard`
- `shadowRaised`
- `methodGetColor`
- `methodPostColor`
- `methodPutColor`
- `methodPatchColor`
- `methodDeleteColor`
- `methodOptionsColor`
- `customCss`

`theme.darkMode` controls whether dark-mode variables are emitted.

Example:

```ts
theme: {
  designSystem: "api-ide",
  overrides: {
    contentWidth: "1040px",
    densitySpace: "10px",
    methodGetColor: "#22c55e",
    methodPostColor: "#3b82f6"
  },
  darkMode: true
}
```

Top-level token fields and `theme.preset` are accepted for migration compatibility. New configs should prefer `theme.designSystem` plus `theme.overrides`.

## layout

`layout` stores documentation shell preferences:

```ts
{
  nav: "sidebar",
  toc: "right",
  footer: true,
  breadcrumbs: true,
  editUrl: "https://github.com/acme/docs/edit/main",
  announcement: "v1.0 is available"
}
```

`layout.nav` can be `sidebar`, `topbar`, or `hybrid`. `layout.toc` can be `right`, `inline`, or `hidden`. `layout.footer` and `layout.breadcrumbs` default to `true`. `layout.editUrl` stores an optional edit-link base URL. `layout.announcement` stores optional site-wide announcement text.

## plugins

`plugins` is optional and supported from TypeScript config files:

```ts
plugins: [
  {
    name: "html-marker",
    transformManifest(manifest) {
      return manifest;
    },
    transformHtml(html, route, manifest) {
      return html;
    },
    validate(manifest) {
      return [];
    }
  }
]
```

Plugins run in array order. `transformManifest` runs after Documentee has loaded content, OpenAPI specs, locales, and versions. `transformHtml` runs when static/dev HTML is rendered. `validate` adds diagnostics to the normal validation result. Plugins are intentionally narrow: they can extend generated output, but they do not replace content loading or fork the manifest pipeline.

## seo

`seo.titleTemplate` formats page titles. `seo.image` sets a default Open Graph image. `seo.twitterCard` can be `summary` or `summary_large_image`. `seo.sitemap` controls `sitemap.xml`. `seo.robots` controls `robots.txt`.

## redirects

`redirects` emits static redirect artifacts:

```ts
{ from: "/old", to: "/new", status: 301 }
```

Supported statuses are `301`, `302`, `307`, and `308`.

## docs.json Compatibility

`docs.json` supports the same main fields. `colors.primary` maps to `theme.primaryColor` for Mintlify migration compatibility.
